## What this does not show

- **OAuth 2.1 with PKCE, Protected Resource Metadata and a remote HTTPS URL are roadmap.** The server runs on `127.0.0.1` for local use; off localhost it requires a bearer token, which is not Amazon's account linking.
- **Security and data policies** are not written yet. The demo uses fictional farm data only.
- **Tool information refreshes only on deploy.** If a tool name, description or schema changes, the add-on has to be deployed again for Alexa+ to see it; nothing here tests that.
- **Nothing here ran on an Alexa+ device**, through Alexa's speech composition, or through Amazon's review.
- The latency is measured on localhost with simulated data and no model call; it is not a production figure.
- The draft listing in `docs/addon-package/addon.json` uses placeholder URLs and images, and its field names are this project's assumption, not Amazon's schema. Only its length limits and counts are checked (`tests/harness/test_addon_draft.py`).
