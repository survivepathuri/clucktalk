## What this does not show

- **OAuth 2.1 with PKCE, Protected Resource Metadata and a remote HTTPS URL are roadmap.** The server runs on `127.0.0.1` for local use; off localhost it requires a bearer token, which is not Amazon's account linking.
- **Security and data policies** are not written yet. The demo uses fictional farm data only.
- **Tool information refreshes only on deploy.** If a tool name, description or schema changes, the add-on has to be deployed again for Alexa+ to see it; nothing here tests that.
- **Nothing here ran on an Alexa+ device**, through Alexa's speech composition, or through Amazon's review.
- **Latency:** our p50 and p95 are server times on localhost in mock mode, and Amazon's 500 ms requirement is a round trip that includes the network, so we do not claim to meet it end to end. There is no model call and the data is simulated.
- The draft listing in `docs/addon-package/addon.json` follows the `addon.json` schema reference on the QuickStart page (as read by the project owner) and uses placeholder URLs and images; nothing was deployed and the Alexa AI CLI was not used (FL-024). Only its field names, counts and length limits are checked (`tests/harness/test_addon_draft.py`), which is not an Amazon validation. See `docs/addon-package/NOTE.md`.

## How the Simulator speaks MCP

The Simulator is a web app: browser UI plus a backend MCP client that sends initialize (protocolVersion 2025-11-25), tools/list and tools/call to the MCP server over Streamable HTTP. The browser page itself only calls the Simulator's own backend (`src/clucktalk/simulator/static/app.js:333`); the backend client is `src/clucktalk/simulator/mcp_client.py:84-122` (`initialize` with protocolVersion 2025-11-25, `notifications/initialized`, `tools/list`) and `src/clucktalk/simulator/app.py:652` (`tools/call`). A captured exchange is in the README, section "How the Simulator speaks MCP".
